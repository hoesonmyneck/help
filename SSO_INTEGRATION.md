# Интеграция перехода с портала ecosystem.enbek.kz → interaction.enbek.kz

Документ для команды портала. Описывает доверенный переход (SSO): портал авторизует
человека по ЭЦП (ФЛ/ЮЛ) на своей стороне и перенаправляет уже авторизованного
пользователя в нашу систему по нашему URL с постоянным токеном.

---

## Что мы предоставляем

**URL (точка входа):**
```
https://interaction.enbek.kz:8443/api/auth/sso
```

**Постоянный токен (общий секрет):** выдаётся отдельно (не хранится в этом файле).
Передавать его при каждом обращении. Мы сверяем токен со своим и доверяем переходу.

---

## Как вызывать

Портал перенаправляет браузер пользователя (HTTP 302/303) на наш URL, передавая токен
и личность. Поддерживаются два способа передать токен:

### Вариант A — через query-параметр (обычный redirect браузера)
```
https://interaction.enbek.kz:8443/api/auth/sso?token=<ПОСТОЯННЫЙ_ТОКЕН>&type=fl&iin=900101300001&fio=ИВАНОВ%20ИВАН
```

### Вариант B — через заголовок (рекомендуется, токен не светится в URL)
```
GET https://interaction.enbek.kz:8443/api/auth/sso?type=ul&bin=051140004523
X-SSO-Token: <ПОСТОЯННЫЙ_ТОКЕН>
```

## Параметры

| Параметр | Обязательность | Описание |
|----------|----------------|----------|
| `token`  | да (если не в заголовке) | Постоянный токен. Либо в query `token`, либо в заголовке `X-SSO-Token`. |
| `type`   | желательно | `fl` — физлицо (ЭЦП ФЛ), `ul` — юрлицо (ЭЦП ЮЛ). Если не указан — берём то, что прислано. |
| `iin`    | для ФЛ | ИИН, 12 цифр. |
| `bin`    | для ЮЛ | БИН, 12 цифр. |
| `fio`    | нет | ФИО / наименование (URL-encoded). Сохраняется в профиле. |

## Что происходит на нашей стороне

1. Проверяем токен (constant-time). Неверный → `403`.
2. Берём идентификатор: для `ul` → `bin`, для `fl` → `iin`. Не 12 цифр → `400`.
3. Находим аккаунт по идентификатору; если его нет — **создаём автоматически**
   (доверяем порталу), роль `user`.
4. Ставим httponly-cookie сессии и делаем `303`-редирект на `/` — пользователь
   попадает в дашборд уже авторизованным.

## Коды ответов

| Код | Значение |
|-----|----------|
| `303` | Успех. Редирект на `/` + установлена сессия-кука. |
| `400` | Не передан корректный ИИН/БИН (12 цифр). |
| `403` | Недействительный токен. |
| `503` | SSO не настроен на сервере (не задан `SSO_TOKEN`). |

---

## Замечания по безопасности

- Переход только по **HTTPS** (`:8443`). По HTTP токен передавать нельзя.
- Предпочтительно слать токен в заголовке `X-SSO-Token`, а не в query — query-строка
  попадает в логи/историю/Referer.
- Токен постоянный; при компрометации мы его меняем (новый `SSO_TOKEN` на сервере +
  выдаём порталу новое значение).
- Personal-проверки (ЭЦП ФЛ по ТД/реестру, ЮЛ по БИН из реестра) выполняет **портал**.
  Мы доверяем результату и не делаем повторную ЭЦП.
